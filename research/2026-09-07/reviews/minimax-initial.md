## 结论

现有系统可做“筛选/预警研究原型”，不能做已验证的策略回测：3398 个事件中仅 40 个池有至少两次观察，且 338 个 15 分钟样本全部缺 K 线。当前也没有可审计的收益、成交深度、交易税或成交时点证据。

## 1. 前五大实际缺陷

1. **回测目标变量不存在（代码/重放结果已证）**  
   `replay_summary` 显示 338 个 eligible、priced=0；唯一合法结果是“不可估计”。缺失 K 线被正确标为 unknown，但现状容易被误读为成功回测。  
   **验收**：连续采集完整 1m K 线；报告 eligible、priced、executable、censored 分母，不得将 unknown 计为亏损。

2. **过滤后样本与幸存者偏差（数据事实，非代码“证明结果”）**  
   历史仅保存 board+alerts，拒绝候选未保存；且股票池在当前 replay 中 20/20 因超过年龄被排除。即使跨期收集，Trending 也会天然偏向已热门者。  
   **验收**：保留每个轮次全市场候选及阈值字段；分别报告“全 universe”与“alert-conditioned”结果。

3. **v4 持仓/LP 语义错误风险（代码路径可证，链上事实未证）**  
   系统将 `pool.address` 同时当作池地址和 LP/持有人地址调用 `balanceOf`。对 Uniswap v4，资产在 PoolManager，PoolId 不是持币地址；故 `lp_pct`、最大持有人、LP drain 不可用。  
   **验收**：按 v2/v3 池地址、v4 PoolId+PoolManager 分类；fixture 断言 v4 token balance 不得从 PoolId读取；只有 manager 状态支持时才恢复 LP 指标。

4. **年龄与滚动量“加速”混淆（代码公式已证，效果未证）**  
   5m 量除以 5 与 1h 量除以 60 比较，窗口长度不同；`min_age=3` 实际并未参与安全门，只产生 warning。改变最大年龄/采集频率会改变候选和加速值，却无法隔离样本成熟度。  
   **验收**：预注册年龄截点 3/5/15/30/60/90 分钟；用等长窗口（如 5m/15m/30m）计算  
   \(accel=V_{5m}/(V_{1h}/12)\)，并按年龄分层；全截点结果方向一致才接受。

5. **base/quote、身份及集中度推断不可审计（代码已证存在缺陷）**  
   ticker/name 被用于叙事，`GOOD_QUOTE_SYMBOLS` 把真实币与垃圾 quote 一视同仁；价格/储备/FDV未做单位校验；集中度仅排除一个池地址及粗略 router，合约真实控制人、跨池库存和关联钱包未重建。多池储备相加可能跨池重复计量 token 供应。  
   **验收**：主键用规范化 chain+token/pool 合约；quote 地址白名单；保存原始单位与时间戳；集中度输出“排除池/路由/工厂前、后”，并对 v2/v3/v4/Pons 分模型。

## 2. 更广且可证伪的样本设计

- **来源层**：全量新池 + 定时随机快照 + Trending；按池首次出现时间纳入，保存拒绝原因。
- **失败层**：被安全门拒绝、零卖、跌超40%、撤池、honeypot、税费异常、流动性撤出；不能只留赢家。
- **控制层**：USDG/WETH 等非 meme；orientation 对（MEME/amc）；同 ticker 不同合约；股票/现实主题 vs 动物/加密原生梗。
- **池型层**：v2、v3、v4、Pons v1/v2、其他 launchpad；分别建立标签，不混成一体。
- **状态层**：冷启动、正常、热门/拥挤、崩跌；至少跨数周及不同市场阶段。
- **陷阱**：Trending 偏差、ticker 冒充、缺页误作零、公告时间晚于数据时间、同一 token 多池重复、token 与 pool 创建时间混用、延迟及 API 修订。必须保存版本化原始响应。

## 3. 三个可测试假设

**H1：等长窗口成交加速，而非瞬时涨幅，预测短期延续。**  
输入仅用信号时可得的池龄、5m/15m/30m成交额、唯一买家、储备、买/卖数。基准为同池、同年龄、同流动性的未触发窗口。入场下一根可成交价，15m 后退出；成本 50/200/500bp 敏感性。  
**证伪**：加速加入后样本外净收益、命中率均不升，置信区间包含零，且仅靠涨跌幅排序同样有效。

**H2：多池真实深度能改善可执行性，但必须在 v4/Pons 分型后成立。**  
输入材料池数量、各池独立 quote、reserve、原子级 swap 模拟；排除同池重复。基准单池流动性。入场限单为储备的固定小比例；24h 退出。  
**证伪**：深度不能降低滑点/撤池退出失败，且结果全由当前热门大池贡献。

**H3：0–1 卖单与高买压提供可交易警报，但连续 K 线才可确认。**  
输入买家、卖家、1h涨跌、池龄、税与可卖模拟。基准 BUY 比例阈值。入场下一根价，-20% 止损、+35% 止盈、最长4h；无法成交按未实现。  
**证伪**：扣除税、滑点后收益不优于简单买压规则。

## 4. 最低可复现回测规范

按规范化合约 ID 关联；信号生成后最近下一根开始时执行，固定延迟场景为 1/5/30 秒；Telegram 时间不作为执行时间。缺 K 线、零价、OHLC 矛盾、储备突变均 unknown/censored；完整/删失分母并报。保存 token 税、动态税、池费率；测试 50/200/500bp 及费用组合。TP/SL 分别按保守（止损先）和乐观（止盈先）两套明确规则。撤池后退出若无买方记失败/撤单，不按零成交价计价。token 组按 chain+合约；多池视为相关事件，训练/阈值拟合不得跨样本隔离。采用按时间 purge/embargo 的 walk-forward split。输出事件数、暴露、命中率、均值/中位净收益、最大回撤、换手、容量，以及 bootstrap/区块自助法置信区间；另做时代、Ticker、池型分层和 placebo 随机化。

## 5. 第一版范围与验收标准

**现在可合法运行**：数据审计、规则重放、阈值敏感性、候选/拒绝漏斗、v2/v3/v4/Pons 身份检查、缺失率与警报延迟报告；不能声称收益、胜率或 alpha。

**必须新增采集**：连续1m OHLCV、原子级报价/交易模拟、税费、池创建与事件日志、储备/撤池、失败池、跨池库存、原始 API 版本和同步时间戳。

**首版验收门槛**：  
1. 至少覆盖一个完整市场阶段且预先固定；2. 有效信号覆盖率≥95%，否则不计 PnL；3. 随机抽取事件逐笔重算可复现；4. v4 fixture 100% 通过身份/LP测试；5. 所有多池 token 均有链上身份与去重规则；6. 成本、延迟、TP/SL 保守规则下仍为正，且留出期方向一致；任一不满足则仅发布“无可验证回测结果”。
